Final recommendations

One decision document consolidating three reports written from Stefan Meury's feedback: Simpler layout, consistent galleries (points 1 and 2), Monthly Challenge rounds (points 3 and 4) and What we can learn from fotocommunity. Where the reports overlapped or disagreed, this page picks one answer and says why.

Every recommendation has a mockup. Photos, titles, authors and vote counts are real, read from the live site on 25 October. Dates marked as illustrative, and anything shown as "yours", are placeholders.

Starting pointStefan's five points

1The page is constructed and laid out very complexly.
2Unsorted and not standardized, so it's not easy to see categories or competition galleries.
3The monthly competitions are not separated.
4It's difficult to see your own result, and there is no email with your own rank.
5The settings page doesn't show the user status. It has to have unique features.

Measured on the live site the same day: the first photo sits about two phone screens down on the homepage and on Photo Feedback; every gallery is ordered by last reply, not by date posted; October and September entries share one stream; four different card formats are in use; category 12 carries three different names depending on where you look.

10 · Results for everyone, and a personal rank for entrants Admin Server

Step 1 found already live, 30 October 2026; no change made. Announcements (5) is in default categories watching first post (value 13|5, with Live-Webinare), and all 24 members sampled have category 5 on that level, so every new Announcements topic already notifies, and emails, every member through their own preferences. Discourse does not allow one category in two default lists, and full "watching" would add an email for every reply, so Oğuzhan decided to keep first-post watching. default categories watching stays empty. Verified by reading /admin/site_settings.json and the users' watched_first_post_category_ids.

From: Challenge report 4.2, fotocommunity report #3. Decided 25 October: everyone hears the results, not only entrants.

How Discourse emails all members. Discourse has no "email everyone" button, but it has the equivalent: every member who watches a category gets an email for each new topic in it. The site setting default categories watching makes a category watched for everyone, and when you change it Discourse offers to apply it to all existing users as well. Set it to Announcements once, and every topic posted there reaches every member's inbox, through their own notification settings, so people who turned emails off stay off. The club newsletter in spc-be stays the channel for non-members.

  • Step 1, admin: add Announcements (category 5) to default categories watching and apply it to existing users. From then on an Announcements topic is an email to the whole club. Done 30 Oct
  • Step 2, server: a Rails runner script in server/, deployed like challenge-vote-reset.rb: systemd timer, read-only by default, acts only with SPC_APPLY=1. Trigger: a completed round with a winner-tagged topic. It posts one Announcements topic with the winner, the top three, the entry and vote counts and a link to the round page. Marks the round as announced (custom field on the brief topic) before posting, so a rerun never posts twice.
  • Step 3, same script: one personal message per entrant from SPC Bot, in their site language, with their rank and all their entries. This is the only way to put "your rank" in an email; the announcement cannot be personalised. Entrants also see the same number on the round page (#8).
  • Crowning in the staff panel stays the only action staff take. Dry-run on September's data first; let it post for real for October's results in early November.

12 · Membership status on profile and settings Theme spc-be

From: fotocommunity report #6

What Discourse knows today, and why that is not enough. Discourse only knows what spc-be tells it, and today that is one fact: the user is in group 40, or not. "Member" is therefore showable now. "Member since July 2026, renews 1 July 2027" is not, because those dates live only in spc-be. Three ways to get them across, in plain terms:

  • User fields (recommended). Discourse lets an admin define extra profile fields (Admin → Customize → User Fields), such as "Member since" and "Renews". spc-be would write the dates into those fields the same way it already puts people into group 40, by calling Discourse's API when a membership starts, renews or ends. The theme then reads them like any other profile value. Two fields, one more call in the sync spc-be already does.
  • More groups. spc-be could put people into groups like "trial" or "annual" as well as group 40. That gives a status word, never a date. Fine for the badge, useless for "renews on".
  • Asking spc-be directly. The theme could call an spc-be endpoint from the browser to fetch the dates. That means a new public endpoint in spc-be with its own login check, and a second system every profile page depends on. Avoid.
  • Now, cheap: an "SPC Member" badge on the user card and profile header, from group 40.
  • When spc-be writes the two user fields: a status block at the top of /profile-setup with member since, renewal and trial end, plus a "Manage membership" link to spc-be.

DecisionsTaken on 25 October

  1. August's crown was a mistake. The rule is most votes. #0 became a data fix plus a Crown-panel guard; no jury label anywhere.
  2. Photo Feedback: photos without a critique are always at the top. "Needs feedback" is a strip above the gallery (#5), not a tab; category 7 switches to date posted when it ships.
  3. Results go to everyone as an Announcements topic, emailed to all members by making Announcements watched by default (#10). The personal rank message to entrants is the second step of the same script.
  4. Membership dates reach Discourse as user fields written by spc-be's existing sync (#12). Nothing is built until spc-be writes them.
  5. No client walkthrough. Decisions on what "complex" and "standardized" mean are made here. A fotocommunity account is not needed: everything the review used was visible signed out.
